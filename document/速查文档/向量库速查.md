# Elasticsearch 向量库速查

本文档对应项目中实际使用的五个 ES 索引及其在 RAG 检索 / 长期记忆 / 知识库 / 知识卡片 / 质量追踪中的角色（截至 v4.2）。

当前项目 ES 用途：
- **用户长期记忆** (`fish-user-memory`) — 对话结束后 LLM 抽取的事实，RAG 时召回注入上下文
- **用户私有知识** (`fish-user-knowledge`) — 用户上传文档，Python Worker OCR → 分块 → embedding 写入
- **用户知识卡片** (`fish-knowledge-card`) — confirmed 知识卡片，MySQL 双写同步
- **公共知识** (`fish-public-knowledge`) — 管理员上传的公共文档，所有用户可见
- **RAG 质量追踪** (`fish-rag-trace`) — RAG 全链路质量追踪日志

## 三、索引 mapping

### 3.1 `fish-user-memory`（用户长期记忆）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `keyword` | 文档 ID |
| `user_id` | `keyword` | 所属用户（term filter 必带） |
| `content` | `text` | 事实内容，`ik_max_word` 分词 / `ik_smart` 检索 |
| `embedding` | `dense_vector` | 1536 维，`cosine` 相似度，`index: true` |
| `created_at` | `date` | `epoch_millis` 格式 |
| `doc_id` | `keyword` | 来源文档/会话 ID |
| `source_type` | `keyword` | 固定 `"chat"`（防御 filter 用） |
| `page_number` | `integer` | 页号（对话固定为 null） |
| `chunk_index` | `integer` | 块索引 |

**RAG 检索约束**：
- 文本查询：`match(content)` + `filter(source_type=chat)` + `filter(user_id=当前用户)`
- 向量查询：`knn(embedding, numCandidates=80)` + `filter(user_id)` + `filter(source_type=chat)`
- `source_type=chat` 为防御性 filter，防止历史误写入的文档切片混入记忆上下文

### 3.2 `fish-user-knowledge`（用户私有文档切片）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `keyword` | 文档 ID |
| `user_id` | `keyword` | 上传用户（term filter 必带） |
| `content` | `text` | 分块文本，`ik_max_word` / `ik_smart` |
| `embedding` | `dense_vector` | 1536 维，`cosine` |
| `created_at` | `date` | `epoch_millis` |
| `doc_id` | `keyword` | 来源 `task_id`（关联 `document_metadata`） |
| `page_number` | `integer` | PDF OCR 页码 |
| `chunk_index` | `integer` | 同一页内的块序号 |

**RAG 检索约束**：
- 文本查询：`match(content)` + `filter(user_id=当前用户)`
- 向量查询：`knn(embedding)` + `filter(user_id)`
- **无** `source_type` 字段，通过 `user_id` 隔离

### 3.3 `fish-public-knowledge`（公共文档切片）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `keyword` | 文档 ID |
| `doc_name` | `keyword` | 文档名称（管理员上传时取文件名） |
| `content` | `text` | 分块文本，`ik_max_word` / `ik_smart` |
| `embedding` | `dense_vector` | 1536 维，`cosine` |
| `created_at` | `date` | `epoch_millis` |
| `doc_id` | `keyword` | 来源 `task_id` |
| `page_number` | `integer` | 页码 |
| `chunk_index` | `integer` | 块序号 |

**RAG 检索约束**：
- 文本查询：`match(content)`（无 `user_id` 过滤，全量召回）
- 向量查询：`knn(embedding)`（无 filter）
- **无** `user_id` 字段，所有用户可见

### 3.4 `fish-knowledge-card`（用户知识卡片，v4.1+）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `keyword` | 文档 ID（= 卡片 ID） |
| `cardId` | `long` | 卡片 MySQL 主键 |
| `userId` | `keyword` | 所属用户 |
| `title` | `text` | 卡片标题，`ik_max_word` 分词 |
| `content` | `text` | 卡片正文，`ik_max_word` 分词 |
| `keywords` | `text` | 关键词数组，`ik_max_word` 分词 |
| `cardType` | `keyword` | `concept` / `topic` |
| `sourceType` | `keyword` | `chat` / `manual` / `knowledge` |
| `status` | `keyword` | `pending` / `confirmed` / `rejected` |
| `groupName` | `keyword` | 分组名 |
| `embedding` | `dense_vector` | 1536 维，`cosine` |
| `createdAt` | `date` | 创建时间 |

**RAG 检索约束**：
- 文本查询：`should(match(title) | match(content) | match(keywords))` + `filter(userId)` + `filter(status=confirmed)`
- 向量查询：`knn(embedding)` + `filter(userId)` + `filter(status=confirmed)`
- 三字段文本搜索（title+content+keywords）：比其他 Searcher 只搜 content 更宽，卡片标题通常更短更精确
- `status=confirmed` 过滤：pending/rejected 卡片不参与 RAG 检索

### 3.5 `fish-rag-trace`（RAG 质量追踪，v3.6+）

19 字段异步写入，采样率可配。主要字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `traceId` | `keyword` | 追踪 ID |
| `userId` | `keyword` | 用户 ID |
| `sessionId` | `keyword` | 会话 ID |
| `originalQuery` | `text` | 原始查询 |
| `rewrittenQuery` | `text` | 重写后查询 |
| `expandedQueries` | `text` | 扩展子查询列表 |
| `recallTotalHits` | `integer` | 召回总命中数 |
| `recallDedupedHits` | `integer` | 去重后命中数 |
| `rerankTopScore` | `double` | 精排最高分 |
| `rerankLowestScore` | `double` | 精排最低分 |
| `injectedFactCount` | `integer` | 注入事实数 |
| `totalLatencyMs` | `long` | 总延迟(ms) |
| `createdAt` | `date` | 创建时间 |

## 四、RAG 四路召回并发模型

```
用户消息
  ↓
RagRecall（虚拟线程线程池）
  ├──→ UserMemorySearcher        (fish-user-memory,     user_id + source_type=chat)
  ├──→ UserKnowledgeSearcher     (fish-user-knowledge,  user_id)
  ├──→ UserKnowledgeCardSearcher (fish-knowledge-card,  user_id + status=confirmed)
  └──→ PublicKnowledgeSearcher   (fish-public-knowledge, 无 filter)
  ↓
RRF 分数融合 → DashScope 精排 → Top-K 注入 SystemMessage
```

**并发配置**：

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `fish.rag.recall.per-subquery-size` | `5` | 单子查询每路召回数 |
| `fish.rag.recall.max-sub-queries` | `12` | 最大并行子查询数 |
| `fish.rag.recall.knn-num-candidates` | `80` | kNN 候选集大小 |
| `fish.rag.recall.vector-leg-enabled` | `true` | 向量召回开关 |
| `fish.rag.render.max-injected-facts` | `8` | 注入 SystemMessage 的最大事实数 |
| `fish.rag.render.max-injected-chars` | `4000` | 注入内容最大字符数 |

## 五、Embedding 模型配置

| 用途 | 提供方 | 模型 | 维度 |
|------|--------|------|------|
| 长期记忆写入 | 默认 DashScope | `text-embedding-v2` | 1536 |
| RAG 向量检索 | 默认 DashScope | `text-embedding-v2` | 1536 |
| Python Worker 文档分块 | DashScope（固定） | `text-embedding-v2` | 1536 |

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `spring.ai.dashscope.embedding.options.model` | `text-embedding-v2` | 嵌入模型名 |
| `spring.ai.dashscope.embedding.options.dimensions` | `1536` | 向量维度 |
| `FISH_LLM_EMBEDDING_PROVIDER` | `DASHSCOPE` | 可切 `OLLAMA`，不支持 `DEEPSEEK` |

> **注意**：切换 Embedding 提供方后需重建 ES 索引（维度可能变化），否则 kNN 查询失败。

## 六、ES 写入方速查

| 写入方 | 索引 | 触发时机 | 批次大小 |
|--------|------|----------|----------|
| Java `LongTermMemoryIngestionService` | `fish-user-memory` | 每轮对话结束后异步抽取 | 逐条 index |
| Java `KnowledgeCardEsSyncService` | `fish-knowledge-card` | 卡片确认/编辑时同步双写 | 逐条 save |
| Python `ElasticsearchIndexer` | `fish-user-knowledge` | 用户上传文档 Worker 消费 Stream | 20 条/批 bulk |
| Python `ElasticsearchIndexer` | `fish-public-knowledge` | 管理员上传文档 Worker 消费 Stream | 20 条/批 bulk |
| Java `RagQualityLogger` | `fish-rag-trace` | 每次 RAG 调用后异步写入 | 逐条 index |

**Python Worker**（`storage/elasticsearch.py`）：
- 使用 `elasticsearch-py` 8.x bulk API
- 失败抛异常不部分回滚（保证 MySQL 状态一致性）
- 无论成功/失败均调用 `XACK` 确认 Stream 消息，避免毒消息阻塞

## 七、删除操作

知识库文档删除走三步骤尽力清理（`KnowledgeManageService`）：

```
DELETE /api/knowledge/documents/{taskId}
  → ① ES delete_by_query (按 doc_id + scope_type 定位索引)
  → ② RustFS 删原文件 (minio_path)
  → ③ MySQL DELETE document_metadata
```

每步失败只记录日志不中断，避免留下孤儿资源（残留 ES 数据或 RustFS 文件）。

## 九、完整示例速查

| 场景 | 索引 | 查询简述 |
|------|------|----------|
| 用户 5 的对话记忆召回 | `fish-user-memory` | `match(content)` + `filter(user_id=5, source_type=chat)` |
| 用户 5 的上传文档召回 | `fish-user-knowledge` | `match(content)` + `filter(user_id=5)` |
| 公共知识库搜索 | `fish-public-knowledge` | `match(content)`（无用户过滤） |
| 用户 5 对话事实 kNN | `fish-user-memory` | `knn(embedding)` + `filter(user_id=5, source_type=chat)`，`numCandidates=80` |
| 用户 5 的知识卡片文本搜索 | `fish-knowledge-card` | `should(match(title) | match(content) | match(keywords))` + `filter(user_id=5, status=confirmed)` |
| 用户 5 的知识卡片向量搜索 | `fish-knowledge-card` | `knn(embedding)` + `filter(user_id=5, status=confirmed)` |
| 文档删除 `task-123`（私有） | `fish-user-knowledge` | `delete_by_query(doc_id=task-123)` |
| 卡片 ID=42 确认后 ES 同步 | `fish-knowledge-card` | `save(KnowledgeCardDocument)` 含 embedding |

# Fish-Agent v5.5 可观测性与 Redis 治理

> 日期：2026-06-12
> 主题：Actuator/Micrometer 可观测管道 + 对话/RAG 指标 + Redis key 字典治理
> 2026-06-13 更新：OTel 链路层、OTLP 导出和 Collector 已下线，保留 Prometheus 指标与日志 MDC traceId。

## 一、更新目标

v5.5 补齐两块后端工程化短板：

- 可观测性：引入 Actuator、Micrometer Prometheus 指标端点，补充对话端到端和 RAG 拓扑指标。
- Redis 治理：集中 key 字典、统一 builder、卡片缓存 key 去 `::`、增加 dev-only key 巡检端点。

## 二、核心改动

### 2.1 基础设施

- `pom.xml` 新增并保留 `spring-boot-starter-actuator`、`spring-boot-starter-aop`、`micrometer-registry-prometheus`。
- `application.yml` 保留 `management.server.port=9090`、`/actuator/prometheus` 暴露与指标分位数配置。
- 2026-06-13 已移除 `micrometer-registry-otlp`、`micrometer-tracing-bridge-otel`、`opentelemetry-exporter-otlp`、`docker/otel-collector-config.yaml` 与 compose 中的 `otel-collector`。

依赖核对结果：

- Prometheus registry 为 `1.15.10`，底层是新版 `prometheus-metrics-* 1.3.10`，未使用 simpleclient。

### 2.2 指标

- 新增 `common/metrics/ChatMetrics`：
  - `fish.chat.turn.duration{outcome=success|error}`
  - `fish.rag.recall.duration{leg=text|vector|fusion|rerank}`
- `ChatService.streamChat` 对 SSE 流式生命周期做一次性采样，避免 `onCompletion/onError` 多回调重复 stop。
- `RagRecall` 对文本召回、向量召回、融合、精排分别计时。
- Spring AI Observation 已开启，但 `gen_ai.*` 的真实 Prometheus 字段名和 token usage 是否可见，需要真实模型请求后核对。

### 2.3 OTel 链路下线记录

OTel 链路层（bridge / OTLP 导出 / Collector 容器 / 手埋 span / RAG traceId 关联）已于 2026-06-13 整体下线，保留 Prometheus 指标与日志 MDC traceId。完整改动清单、保留能力边界、验证结果与面试 Trade-off 见 **[v5.6-OTel链路层下线](v5.6-OTel链路层下线-20260613.md)**。

### 2.4 Redis key 治理

- 新增 `common/redis/RedisKeys`，集中声明 session、memory、agent-state、cache、ratelimit、mutex、doc stream key。
- `RedisCacheConfig` 从 `prefixCacheNameWith` 改为 `computePrefixWith`，卡片缓存实际 key 变为：
  - `fish:cache:card:card-detail:{userId}:{cardId}`
  - `fish:cache:card:card-stats:{userId}`
  - `fish:cache:card:card-relations:{userId}`
- 新增 `RedisKeyInspectionController`，仅 `dev` profile 注册，`GET /admin/redis/keys` 使用 SCAN 聚合命名空间与抽样 key。

## 五、面试 Trade-off

| 问题 | 回答要点 |
|------|----------|
| 为什么只保留 Prometheus？ | 不维护 Collector 容器，避免 OTLP 导出连接失败日志；Prometheus HTTP 端点零额外基础设施，仍能覆盖 JVM/HTTP/业务指标。 |
| 为什么下线 span？ | 当前是单体部署，日志 MDC traceId + 业务指标已满足排查；分布式链路追踪收益不足以抵消 Collector 运维成本。 |
| SSE cancel 怎么保证指标？ | `ChatTurnLifecycle` 用 CAS 统一结束 Timer，timeout/client disconnect/Reactor error/complete 多回调只记一次。 |
| 为什么保留 @Observed？ | 移除 OTel bridge 后不再产出 span，但 `@Observed("rag.recall")` 仍可作为 Micrometer 观测入口。 |
| Redis key 为什么去 `::`？ | Spring Cache 默认 `cacheName::key` 不利于统一命名空间巡检；`computePrefixWith` 能保持 cacheName 语义并改成单冒号树。 |
| 巡检端点为什么只用 SCAN？ | Redis 单线程，KEYS 会阻塞；SCAN 可增量遍历且 sampleLimit 封顶。 |

## 一、v3.0 一句话增量

将后端 `com.yuyu.fishagent` 包从**按技术层分包**（controller/service/dto/config/entity/mapper 混合）重构为**按业务域分包**（agent/chat/rag/memory/auth/llm/common），84 个文件移动 + 1 个 `@MapperScan` 修改 + 1 个 `spring.factories` FQCN 更新。零功能变更，零接口变更。

---

## 二、重构动机

重构前，`config/` 混了 12 个不相关的配置文件，`dto/` 混了 18 个 DTO，`controller/`、`service/` 同理。修改一个业务功能需要跨 4-5 个包改动，关联关系不清晰。

重构后每个业务模块自包含 controller / service / dto / entity / mapper / config，修改一个功能只需关注一个包。

## 四、关键设计决策

### 4.1 history/ 放在 chat 而非 memory

**问题**：如果 history（对话历史存储）放在 memory 模块，会形成 chat ↔ memory 循环依赖——ChatService 依赖 ShortTermMemoryStore（memory），而 RustFsChatMemoryStore 依赖 ChatMetadataService（chat）。

**决策**：history/ 移入 `chat/history/`。对话历史本质是"聊天记录持久化"，属于 chat 职责。

### 4.2 ChatMessageDTO 放在 common/dto

**问题**：ChatMessageDTO 同时被 memory（ShortTermMemoryStore、MemoryPromptBuilder）和 chat（ChatService、ChatMemoryStore）使用。

**决策**：放到 `common/dto/`。它是通用消息结构体（role + content），不属于任何单一模块。

### 4.3 RAG pipeline 从 agent/memory/rag/ 提升为独立模块

**问题**：RAG 管道原来嵌套在 `agent/memory/rag/` 三层深处。

**决策**：提升为独立 `rag/` 模块，路径从 `agent.memory.rag.*` → `rag.pipeline.*`。

### 4.4 PublicKnowledgeDocument / UserMemoryDocument 放在 rag/document

**问题**：这两个 ES 文档类原来在 `agent/memory/longterm/` 下，但实际只有 rag 模块的代码使用。

**决策**：移入 `rag/document/`。ElasticsearchLongTermMemoryStore 不依赖它们。

## 五、模块间依赖关系

```
chat ──→ agent, memory, rag, auth, common
rag  ──→ memory, auth, common
memory ──→ common
agent ──→ 自包含（config 内聚）
auth  ──→ 自包含
llm   ──→ 自包含
common ──→ 自包含
```

### 已知双向依赖（设计妥协）

`memory.longterm.ElasticsearchLongTermMemoryStore` 引用 `rag.document.UserMemoryDocument`，形成 memory ↔ rag 双向引用。原因：重构前两者在同一包 `agent/memory/longterm/` 下。编译和运行无影响（同 JVM、无循环 bean 注入），后续可考虑将 `UserMemoryDocument` 移入 `memory/longterm/` 消除。

## 八、短期记忆懒压缩流程（调试时梳理）

在排查 `RedisShortTermMemoryStore.save()` 未被调用时，梳理了完整的短期记忆读写链路：

### 写入链路

```
每轮对话结束 → ChatService.triggerMemoryCompressionIfNeeded()
  → fullHistory.size() < summaryTriggerThreshold(默认30) ?
    → 是：跳过，不写入 Redis
    → 否：CompletableFuture.runAsync(
        MemoryCompressionService.compress()
          → LLM 生成摘要
          → saveShortTermMemory()
            → RedisShortTermMemoryStore.save(summary, recentMessages)
      )
```

### 读取链路

```
每轮新对话开始 → ChatService.buildMessages()
  → shortTermMemoryStore.load(sid)
    → Redis 有数据 → 用 summary + recentMessages
    → Redis 无数据 → 降级到文件历史尾部截取最近 20 条
```

### 设计含义

| 阶段 | 数据来源 | 模型看到什么 |
|------|----------|-------------|
| 前 30 条消息（未压缩） | 文件历史尾部截取 | 最近 20 条原始消息 |
| ≥ 30 条后首次压缩 | Redis | LLM 生成的压缩摘要 + 最近 20 条消息窗口 |
| 后续每轮 | Redis | 每次压缩更新摘要 + 窗口滑动 |

## 一、一句话定位

Fish-Agent 是基于 **Spring Boot 3.5 + Spring AI Alibaba ReAct** 的全栈智能体应用，具备工具插件化调用、三层记忆体系（文件/Redis/ES）、可选 RAG 召回、对话与嵌入模型可分别路由，前端以 **Vue 3 + SSE** 流式呈现对话过程。

## 二、技术栈汇总

**后端**

- JDK 21（虚拟线程 `spring.threads.virtual.enabled=true`）
- Spring Boot 3.5.13（锁定，与 Spring AI Alibaba 1.1.2.x 对齐，不升 4.x）
- Spring AI Alibaba Agent Framework 1.1.2.0（`ReactAgent` + `ModelCallLimitHook`）
- Spring AI BOM 1.1.4
- 对话模型：DashScope（通义千问）/ Ollama（本地，如 qwen2.5:7b）——可切换
- 嵌入模型：DashScope Embedding / Ollama Embedding——与对话独立配置
- Redis（短期记忆摘要 + 滑动窗口）
- Elasticsearch `dense_vector`（长期事实向量写入与 RAG 召回）
- 文件系统 JSON（原始会话历史 `data/history/{sid}.json`）
- Jsoup 1.18.3（网页抓取工具）
- Spring Boot Mail（邮件工具）
- Lombok 1.18.42
- MySQL 驱动（运行时依赖，预留关系型扩展）
- JUnit 5 + Mockito（测试）

**前端**

- Vue 3.5.13 + TypeScript 5.6
- Vite 6.0.7（开发服，`/api` 反向代理后端 :8080）
- Element Plus 2.10.0 + @element-plus/icons-vue
- Pinia 3（状态管理）
- marked 14 + highlight.js 11（Markdown 渲染 + 代码高亮）
- unplugin-auto-import / unplugin-vue-components（按需自动导入）

## 五、后端项目亮点（简历向）

**1. 基于 Spring AI Alibaba 构建 ReAct 智能体，落地工具 SPI 插件体系**

- 自定义 `AgentToolProvider` SPI 接口，内置 5 个 + 外部 5 个工具，新增工具仅需「建类 + `@Component`」，`ToolRegistry` 自动发现并做单工具失败隔离，零侵入业务层。
- 外部工具基于 `@ConditionalOnProperty` 按配置懒装配（高德天气/地理、Tavily/博查搜索、邮件），key 缺失时 Agent 仍正常运行。

**2. 三重防死循环机制，保障生产级稳定性**

- `CompileConfig.recursionLimit`（图节点切换硬上限）+ `ModelCallLimitHook`（模型调用次数上限，触达后优雅追加 AssistantMessage 直跳 end）+ `AgentStatus` 原子状态机（IDLE/RUNNING/FINISHED/ERROR），三重保险互补。

**3. 三层记忆分层设计，接口-实现解耦**

- **文件历史**（完整事实源）/ **Redis 短期摘要 + 滑动窗口**（控上下文长度）/ **Elasticsearch dense_vector 长期事实**（可检索），每层有独立 SPI（`ChatMemoryStore` / `ShortTermMemoryStore` / `LongTermMemoryStore`），实现可替换。
- 短期摘要压缩明确「只写 Redis」，长期录入「只写 ES」，两条链路职责不交叉，避免摘要重复灌入向量索引。

**4. 长期事实质量控制：Prompt + 规则过滤双保险**

- `LongTermMemoryPromptBuilder` 约束模型仅提取稳定用户事实；`LongTermMemoryFactSanitizer` 在写入 ES 前过滤产品能力介绍类误抽取，保证向量索引的信噪比。

**5. 可运维的 RAG 管道（可选重写 + 始终扩展 + 全索引召回）**

- `fish.rag.enabled` 总开关；`rewrite-enabled` 手控查询重写；`SubQueryExpander` 开启后始终多查询并发召回；ES 同时支持文本 `match` 与可选 kNN 向量腿；召回结果合并渲染为**单条** `SystemMessage` 片段注入上下文。

**6. 对话与嵌入模型独立路由，解决双 Starter Bean 歧义**

- `FishLlmEnvironmentPostProcessor`（`EnvironmentPostProcessor` + `META-INF/spring.factories`）在 Spring Boot 早期写入 `spring.ai.model.chat`，确保 DashScope/Ollama 条件装配的唯一性。
- `fishPrimaryChatModel`（`@Primary` ChatModel）和 `fishPrimaryEmbeddingModel`（`@Primary` EmbeddingModel）分别托管，Chat 与 Embedding 可独立选型。

**7. 全栈 SSE 流式协议设计**

- 后端 `ChatService` 订阅 `Flux<NodeOutput>`，实现段聚合、全文重复、末尾长段重复三级去重，再推 SSE chunk；前端 `api/chat.ts` 用 `fetch + ReadableStream` 解析，支持 `AbortSignal` 取消。
- SSE 事件契约：`session` / `chunk` / `tool` / `done` / `error`，工具调用过程可视化。

**8. 文件历史并发安全写入**

- `FileSystemChatMemoryStore` 每个 sessionId 对应一把 `ReentrantLock`，写入采用临时文件 + `ATOMIC_MOVE`，降低并发写入导致文件损坏的风险。

## 六、近期可改进项（v1.x → v1.4+）

- **会话级并发互斥**：`ChatService` 目前依赖前端 streaming 期间禁用按钮兜底，后端可加 `ConcurrentHashMap<String, AtomicBoolean>` 做 sid 级抢占，返回 409 而非让两个请求同时写同一会话文件。
- **`MAX_ITER_REACHED` 状态完善**：枚举值已定义，触达 `ModelCallLimitHook` 后目前状态走 `FINISHED`；可在 Hook 回调里显式 `transitionTo(MAX_ITER_REACHED)` 并向前端推 `event: warn`，方便排查 Agent 兜底路径。
- **工具调用气泡**：SSE `event: tool` 已设计，`ChatService.handleNode` 对 `ToolResponseMessage` 节点 emit 对应事件即可；前端 MessageBubble 已有工具气泡组件，只需连通。
- **独立记忆模型**：短期压缩和长期事实抽取目前复用主 `ChatModel`；可提取 `MemoryModelClient` 接口，配置更便宜的小模型（如本地 Ollama qwen2.5:3b），降低每轮推理成本。
- **ES 脏文档清理**：历史写入的「产品能力说明」类文档已被 `LongTermMemoryFactSanitizer` 过滤（仅新增），老文档需手动在 Kibana 或 Delete by Query 清理；可提供 `POST /api/memory/long-term/purge` 管理接口。
- **长期事实去重**：目前写入前无相似度或 hash 去重，同一事实可能多次写入 ES；可按 `userId` + embedding 余弦相似度做幂等过滤。
- **异步线程池独立**：`CompletableFuture.runAsync` 默认使用 ForkJoinPool；短期压缩和长期录入可配置独立线程池，限制并发数与队列深度，防止 LLM 调用风暴。

## 七、后期推荐改造方向

**功能演进**

- **多租户 / 用户体系**：当前以 `sessionId` 区分会话，可引入 `userId`，长期记忆 ES 索引按用户隔离，RAG 召回也按用户维度过滤，支撑多用户部署。
- **多模态输入**：Spring AI 已有 `ImageMessage` 支持；可扩展前端上传区，接入支持视觉的 DashScope VL 模型，工具层增加图片处理能力。
- **Agent 编排升级**：从单 `ChatAgent` 扩展为多 Agent 协作（Supervisor 模式），如规划 Agent + 搜索 Agent + 写作 Agent，适合复杂任务。
- **知识库管理**：提供文档摄入（PDF/Word/网页）接口，写入 ES 向量索引作为 RAG 语料，支持结构化知识管理。

**工程质量**

- **可观测性**：接入 Micrometer + Prometheus，暴露工具调用耗时、RAG 命中率、LLM token 消耗、记忆触发次数等 Metrics；集成 Zipkin/Grafana Tempo 做调用链追踪。
- **接口文档**：引入 SpringDoc OpenAPI 3，自动生成 Swagger UI，方便前后端协作与对接。
- **容器化部署**：编写 Dockerfile（后端 + 前端分离构建）和 `docker-compose.yml`（含 Redis、Elasticsearch、Ollama 服务），一键本地/测试环境拉起。
- **CI/CD**：GitHub Actions 配置：push 触发 Maven 测试 + 构建，PR 阶段运行 `LongTermMemoryFactSanitizerTest` 等关键单测。
- **ES 索引版本管理**：当前仅在索引不存在时创建；增加索引 mapping 版本字段和迁移策略（如 alias 滚动），支持 `embedding-dimensions` 变更时平滑迁移。

**体验优化**

- **前端断线重连**：SSE 长连接断开后自动重试，恢复流式输出；`done` 事件与增量拼接的一致性校验。
- **长会话性能**：消息列表引入虚拟滚动（如 `vue-virtual-scroller`），防止超长会话 DOM 爆增卡顿。
- **多模型切换 UI**：前端增加模型选择下拉，通过请求头或参数动态路由后端模型，无需重启。

## 八、HTTP / SSE 接口速查

| Method | Path | 说明 |
|--------|------|------|
| POST | `/api/chat/stream` | 流式对话（SSE，5 分钟超时），body: `{ sessionId?, message }` |
| GET | `/api/chat/sessions` | 列出所有会话摘要（按 updatedAt 倒序） |
| GET | `/api/chat/sessions/{sid}` | 取会话历史消息 |
| DELETE | `/api/chat/sessions/{sid}` | 删除会话 |
| POST | `/api/memory/compress` | 手动触发短期摘要压缩（调试用） |

SSE 事件：`session`（sid 回推）/ `chunk`（token 增量）/ `tool`（工具调用）/ `done`（流结束）/ `error`（异常）

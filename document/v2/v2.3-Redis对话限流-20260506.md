## 一、v2.3 一句话增量

对 **`/api/chat/**`** 在 **`GlobalAuthInterceptor` 之后** 插入 **`RateLimitInterceptor`**：按 **`userId`** 维护 Redis **令牌桶**（允许短时突发，默认等价 **60 次/分钟**）与 **`POST /api/chat/stream` 专用 SSE 并发计数**（默认每用户 **2** 路）；超限返回 **HTTP 429** + **`application/json`**，通过 **`code`** 区分 **`RATE_LIMIT_EXCEEDED`** 与 **`CONCURRENT_LIMIT_EXCEEDED`**；SSE 连接结束时由 **`ChatService`** 与拦截器 **INCR 对称 DECR**，并用 **key TTL** 兜底防泄漏。

---

## 二、拦截器链位置

```
GlobalAuthInterceptor  →  RateLimitInterceptor  →  PermissionInterceptor
        （/api/**）              （仅 /api/chat/**）           （/api/**）
```

| 顺序 | 说明 |
|------|------|
| 必须在 Auth 之后 | 限流 key 为 `userId`，依赖 **`UserContextHolder`**（由 GlobalAuth 写入） |
| 在 Permission 之前 | 高频滥用请求尽早 **429**，减少权限分支开销 |
| `userId == null` | **放行**（防御性：避免拦截器顺序被误调导致 NPE） |

---

## 三、Redis Key 与脚本职责

| Key | 类型 | 含义 | TTL（默认） |
|-----|------|------|-------------|
| `fish:ratelimit:token:{userId}` | Hash | `tokens`、`lastRefillTime`（毫秒） | `fish.rate-limit.token-bucket.key-ttl`（120s） |
| `fish:ratelimit:sse:{userId}` | String | 当前活跃 SSE 连接整数计数 | `fish.rate-limit.sse-concurrent.key-ttl`（300s） |

- **令牌桶**：单 Lua 内完成 refill（按 `refillRate` tokens/s）、consume、写回 Hash、`EXPIRE`。  
- **SSE 并发**：`INCR` 后若 `> maxConnections` 则 **`DECR` 回滚**并返回 **-1**（原子拒绝）。  
- **DECR**：独立 Lua，仅在计数 **> 0** 时递减，避免 key 不存在时减成负数。

Redis 执行异常时 **`RateLimitService`** **fail-open**（放行并打 WARN），避免 Redis 故障拖垮全站对话。

---

## 四、SSE 计数生命周期

| 阶段 | 行为 |
|------|------|
| **INCR** | **`RateLimitInterceptor`** 对 **`POST …/api/chat/stream`** 且令牌桶已通过时执行 Lua |
| **DECR** | **`ChatService.streamChat`** 内 **`AtomicBoolean`** 保证至多一次的 **`releaseSseSlotOnce`**，合并进 **`SseEmitter` 的 `onTimeout` / `onCompletion` / `onError`**（与原有 **`disposable.dispose()`** 同回调，避免覆盖注册） |
| **提前返回** | 空 **`message`**、组装上下文异常等路径须 **`releaseSseSlotOnce.run()`**，否则拦截器已 INCR 会泄漏 |
| **兜底** | **`fish:ratelimit:sse:{userId}`** TTL 过期后计数自然失效 |

## 六、配置与环境变量

**`application.yml`（`fish.rate-limit`）**

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `enabled` | `true` | `FISH_RATE_LIMIT_ENABLED` |
| `token-bucket.capacity` | `60` | 桶容量（突发上限） |
| `token-bucket.refill-rate` | `1.0` | 令牌/秒（约 60/分钟） |
| `token-bucket.key-ttl` | `120` | token Hash TTL（秒） |
| `sse-concurrent.max-connections` | `2` | 每用户最大并发 SSE |
| `sse-concurrent.key-ttl` | `300` | SSE 计数 TTL（秒，约 5 分钟兜底） |

## 七、前端与 429 响应

限流发生在 **`preHandle`**，**SSE 流尚未建立**，响应 **`Content-Type: application/json`**。

```json
{"code":"RATE_LIMIT_EXCEEDED","message":"Too many requests","retryAfter":3}
{"code":"CONCURRENT_LIMIT_EXCEEDED","message":"Too many concurrent connections"}
```

**`fetch` POST SSE**：先读 **`response.status === 429`**，再 **`await response.json()`** 按 **`code`** 分支提示；非 429 再按 SSE 流解析。

## 八、明确边界（本版本不做）

- 不按 IP、不按全局限流网关  
- 不限流 **`/api/auth/**`、`/api/knowledge/**`** 等非 **`/api/chat/**`** 路径  
- 不限流数据持久化 / 管理后台统计  
- 无 Spring Cloud Gateway / Sentinel

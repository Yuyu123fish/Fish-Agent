## 二、问题与修复

### 2.1 新会话首条消息阻塞（Bug 1）

**问题现象**：新建会话后发送首条消息，短时间内仍显示欢迎页，直到后端返回 `session` 事件才出现消息。  

**根因**：消息被写到 `messagesBySid['__pending__']`，但 `messages` 计算属性读取的是 `messagesBySid[activeSid.value]`，当 `activeSid=''` 时读取不到新消息。  

**修复要点**（`frontend/src/store/chat.ts`）：
- 发送入口保存 `apiSid`（原始 sid）并在新会话时立即设 `activeSid='__pending__'`  
- `assignedSid` 初始化改为 `apiSid`，保持 `onSession` 中 `if (!assignedSid)` 语义正确  
- `onChunk` / `onTool` 直接使用 `activeSid.value`  
- `finally` 增加兜底：若始终未拿到真实 sid，清理 `__pending__` 并重置 `activeSid=''`

---

### 2.2 disabled 按钮暗色发白（Bug 2）

**问题现象**：流式生成中，`plain` 按钮禁用后背景偏白，与暗色主题冲突。  

**修复要点**：
- `SessionSidebar.vue`：`新会话` 按钮增加 `.is-disabled` 明确变量覆盖  
- `KnowledgeUpload.vue`：分别覆盖 `primary plain` 与 `default plain` 两类 disabled 样式  
- 统一策略：`background=transparent`，边框/文字跟随主题变量，`opacity=0.5`

---

### 2.3 滚动条默认样式不统一（Bug 3）

**修复文件**：`frontend/src/style.css`  

新增：
- `::-webkit-scrollbar` / `::-webkit-scrollbar-thumb` / `::-webkit-scrollbar-track`  
- Firefox `scrollbar-width: thin` + `scrollbar-color`

### 2.4 页面美化与交互细节（Bug 4）

**MessageList.vue**
- `scrollToBottom(force=true)` 使用 `scrollTo(..., behavior:'smooth')`
- 自动追随输出仍保留 `scrollTop` 直达，避免流式渲染抖动
- 欢迎建议卡片新增左侧 accent 线与更大圆角

**MessageBubble.vue**
- 用户气泡增加轻阴影，暗色模式下阴影参数增强

**SessionSidebar.vue**
- 列表项过渡扩展为 `background + transform`
- hover 增加 `translateX(2px)` 轻反馈

**ChatInput.vue**
- 发送按钮按压态缩放（`:active`）

## 五、前端全面美化追加说明（2026-05-08）

### 5.1 范围与约束

- **涉及文件（8 个，均在 `frontend/src/`）**：`style.css`、`views/LoginView.vue`、`views/ChatView.vue`（布局校验，无功能性改动）、`views/KnowledgeView.vue`、`components/SessionSidebar.vue`、`components/MessageList.vue`、`components/MessageBubble.vue`、`components/ChatInput.vue`。  
- **约束**：零新增 npm；仅样式与模板结构调整；**不改** Pinia store、HTTP API、路由与对话逻辑。  
- **暗色**：所有新增样式均在 `[data-theme='dark']` 下有对应覆盖或使用主题变量。

### 5.2 技术要点（文档级备忘）

- **侧栏品牌**：emoji 与文案拆分（`.brand-emoji` / `.title`），避免渐变 `-webkit-background-clip: text` 导致 emoji 不可见。  
- **知识库页 header**：scoped 样式下按钮文字需 `.kb-header :deep(.el-button)` 才能命中 Element Plus 根节点。  
- **Markdown 代码块**：全局 `.markdown-body pre` 保留 `padding` 作为裸 `<pre>` 兜底；`.markdown-body .code-block pre { padding: 0 }` 与 MessageBubble 自定义 `renderer.code` 输出的 `.code-block` 结构配合。

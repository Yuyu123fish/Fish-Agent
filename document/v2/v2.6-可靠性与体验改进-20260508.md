## 一、v2.6 一句话增量

1. **SSE persist 异常安全**：`ChatService.onComplete` 中 `persist()` 独立 try-catch，持久化失败不再阻塞 `emitter.complete()`，避免 SSE 连接挂死 5 分钟。
2. **会话重命名**：后端新增 `PATCH /api/chat/sessions/{sid}` 端点 + `ChatMetadataService.renameTitle()` 所有权校验；前端侧栏编辑按钮触发内联重命名；CORS 白名单补充 `PATCH`。
3. **409 并发冲突友好提示**：前端 `streamChat` 解析 409 JSON body 提取中文 message，替代原始 JSON 裸露。
4. **主题跨 Tab 同步**：`useTheme.ts` 注册 `window.storage` 事件监听，多标签页主题实时同步。
5. **工具调用卡片增强**：`MessageBubble.vue` 新增 `.tool-card` 布局（图标徽章 + 友好中文名 + 可折叠 payload）。
6. **会话删除二次确认**：`SessionSidebar.vue` 删除前弹出 `ElMessageBox.confirm`，防止误触丢数据。
7. **全局错误边界**：`App.vue` 的 `onErrorCaptured` + `main.ts` 的 `app.config.errorHandler` 双层兜底，组件异常展示降级页面而非白屏。
8. **长对话渐进式渲染**：`MessageList.vue` 仅渲染最近 30 条消息，顶部"加载更早消息"按钮追加，100+ 条消息不再 DOM 膨胀卡顿。

## 二、后端改动详述

### 2.1 SSE persist 异常安全

**问题**：`ChatService.onComplete` 回调中，`persist()` 与 `emitter.complete()` 在同一个 try 块。若 `persist()` 抛异常（RustFS 宕机、磁盘满），`safeSend("done")` 和 `emitter.complete()` 均被跳过 → 前端永远收不到 done → SSE 连接挂住直到 5 分钟超时 → 会话锁和 SSE 并发槽被无意义占用。

**方案选型**：

| 方案 | 做法 | 选/不选 |
|------|------|--------|
| **A. persist 独立 try-catch** | persist 单独包裹，失败仍发 done + complete | **选定。** fail-safe：emitter 生命周期不应被持久化阻塞，与同级的异步记忆触发保持一致 |
| B. persist 失败带错误标记 | done 事件加 status 字段 | 需改前端 done 处理，改动面大 |
| C. persist 改异步 | 移到 CompletableFuture | 异步线程 UserContext 已清理，需额外传参 |

**修复文件**：`ChatService.java` onComplete lambda

### 2.2 会话重命名端点

**问题**：会话标题由首条消息自动生成（截断前 200 字），之后无法修改。

**端点设计选型**：

| 方案 | 做法 | 选/不选 |
|------|------|--------|
| **A. PATCH /sessions/{sid}** | RESTful 局部更新 | **选定。** PATCH 语义精确，未来可扩展 |
| B. PUT /sessions/{sid} | 全量替换 | 语义过重 |
| C. POST /sessions/{sid}/rename | 自定义动作端点 | 不符合 RESTful |

**后端实现**：
- `ChatMetadataService.renameTitle()`：`selectOne` 含 `sessionId + userId` 校验所有权，复用 `trimTitle()` 截断，touch `updatedAt`
- `ChatController`：`@RequestBody Map<String, String>`，空标题抛 `IllegalArgumentException` → 全局 400
- `ChatService`：委托层 `renameTitle()` 调用 `chatMetadataService`

**CORS 踩坑**：`WebMvcConfig.addCorsMappings()` 的 `allowedMethods` 缺少 `PATCH`，前端请求因 preflight 被拒返回 403。修复：补充 `"PATCH"`。

**修改文件**：`ChatMetadataService.java`、`ChatService.java`、`ChatController.java`、`WebMvcConfig.java`

## 三、前端改动详述

### 3.1 409 并发冲突友好提示

**问题**：前端 `streamChat` 的非 200 处理直接展示 `HTTP 409：{"code":"SESSION_LOCKED",...}` 原始 JSON。

**方案选型**：

| 方案 | 做法 | 选/不选 |
|------|------|--------|
| **A. 前端解析 409 JSON** | 对 409 特殊处理，提取 message | **选定。** 不破坏后端统一 JSON 格式 |
| B. 后端 409 返回纯文本 | 改 GlobalExceptionHandler | 破坏统一错误格式 |
| C. 前端通用错误解析器 | 所有非 2xx 解析 JSON | 过度设计 |

**设计原则**：后端错误保持统一 JSON（`{ code, message }`），前端按 status + code 精细化消费。

**修改文件**：`frontend/src/api/chat.ts`

### 3.2 主题跨 Tab 同步

**问题**：`useTheme.ts` 不监听 `storage` 事件，多标签页主题不一致。

**方案**：模块顶层注册 `window.addEventListener('storage', ...)`，检测其他标签页的主题变更。`applyTheme` 为函数声明，JS hoisting 保证模块内可用。

**修改文件**：`frontend/src/composables/useTheme.ts`

### 3.3 工具调用卡片增强

**问题**：工具气泡视觉简陋，纯文本显示原始工具名 + payload JSON。

**方案**：`MessageBubble.vue` 新增 `.tool-card` 布局（左侧 `.tool-badge` 图标徽章 + 右侧 `.tool-body` 标题 + 可折叠 payload）。`friendlyToolName` computed 维护工具名→中文名映射，映射表在前端维护（后端只发技术标识符）。默认折叠。

**修改文件**：`frontend/src/components/MessageBubble.vue`

### 3.4 会话删除二次确认

**问题**：删除按钮直接执行，误触丢数据。

**方案**：`ElMessageBox.confirm` 弹出确认框，取消时静默返回。

**修改文件**：`frontend/src/components/SessionSidebar.vue`

### 3.5 全局错误边界

**问题**：组件运行时异常无兜底，白屏。

**方案**：`App.vue` 的 `onErrorCaptured` 捕获组件树异常展示降级页面（"出了点问题" + 重试按钮）；`main.ts` 的 `app.config.errorHandler` 兜底未被捕获的异常。

**修改文件**：`frontend/src/App.vue`、`frontend/src/main.ts`

### 3.6 长对话渐进式渲染

**问题**：100+ 条消息全量 DOM 渲染导致卡顿。

**方案选型**：

| 方案 | 做法 | 选/不选 |
|------|------|--------|
| **A. 渐进式渲染** | 仅渲染最近 30 条 + loadMore 追加 | **选定。** 零依赖、聊天场景特化 |
| B. @tanstack/vue-virtual | 虚拟滚动库 | 新依赖、动态高度复杂 |
| C. 后端分页 | API 分页加载 | 改动面大 |

**实现**：`RENDER_BATCH=30`、`visibleMessages` computed 取 `messages.slice(-renderCount)`、`:key` 使用全局索引保证 loadMore 时已有 DOM 不重渲染、`watch(messages)` 新消息到达时同步扩大窗口。

**修改文件**：`frontend/src/components/MessageList.vue`

### 3.7 AbortController 卸载清理（v2.5 补充）

`chat.ts` 新增 `cleanup()` 函数，`ChatView.vue` 的 `onUnmounted` 调用。组件卸载时 abort 残留 fetch，与后端 SSE 5 分钟超时形成双保险。

**修改文件**：`frontend/src/store/chat.ts`、`frontend/src/views/ChatView.vue`

## 五、核心设计原则

1. **fail-safe**：emitter 生命周期不应被持久化失败阻塞
2. **统一错误格式**：后端所有错误走 JSON，前端按需精细化消费
3. **RESTful 语义**：新增端点用 PATCH 不用 POST/PUT
4. **前后端职责分离**：工具名映射在前端，后端只发技术标识符
5. **CORS 同步**：新增 HTTP 方法端点时必须检查 CORS 白名单

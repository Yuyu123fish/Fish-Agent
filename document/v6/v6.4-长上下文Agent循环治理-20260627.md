## ③ Prompt-cache 排序：时钟锚点置末，让稳定前缀可命中缓存

**Situation**：迁到 DeepSeek V4-Flash 1M 窗口后，每轮 ReAct 整包重发 prompt。DeepSeek 有自动 prompt cache（稳定前缀命中后近乎免费），但会话时钟锚点行（`sessionClockAnchorLine`，秒级时间戳、**跨 turn 必变**）原本是 SystemMessage 的**第一个 token**——从第 0 个 token 起前缀就断，整段 system 前缀每轮全量 miss，缓存红利一口没吃到。

**Task**：让跨轮稳定的段（instruction / 摘要 / 摘录）成为可命中的缓存前缀，降低多轮 ReAct 的边际 token 成本——**不动任何安全语义**（防死循环上限、token 预算），且不破坏时钟锚点功能。

**Action**：
- 抽出 `ChatService.assembleSystemBlock`（package-visible 静态），SystemMessage 段顺序改为**稳定段前置、时钟锚点置末**；重构 `buildMessages` 把"段内容构建"与"段顺序"解耦（各段 lift 成局部量，集中拼装）。
- `emergencyTrim` 的 `requiredSystemText` 同步改稳定前置，降级路径不丢时钟锚点。
- **砍掉 agentState 重排**：核缓存数学后，agentState(recentTools) 与 RAG 都每轮变、谁在前缓存命中长度都一样（稳定前缀同是 instruction+summary+excerpt），**只移 clockLine 即拿全部收益**。
- TDD：先写 `assembleSystemBlock` 顺序不变量测试（红）→ 实现（绿）。

**Result**：
- clockLine 不再是首 token，跨轮稳定前缀 `[instruction + summary + excerpt]` 可命中缓存；新增 `ChatServiceSystemBlockAssemblyTest`（3 条），全量 **252/252 绿**。
- ⚠️ **顺序对是必要不充分**：真实缓存命中增益待 ④（token 观测）证实——instruction ~300 字可能贴近 DeepSeek 缓存最小命中长度下限（约 256–1024 token），且跨轮复用还取决于 cache TTL 与用户回合间隔。

**代码**：`chat/ChatService.java`（`assembleSystemBlock` 新增 / `buildMessages` 重构 / `requiredSystemText` 顺序）；测试 `chat/ChatServiceSystemBlockAssemblyTest.java`。

## 待补（v6.4 其余项，占位）

- **⑤** 终止原因 trace 埋点（LOOP / BUDGET / USER_CANCEL / NORMAL）——把"90% 在 1-3 轮完成"从经验值变可观测事实。
- **②** `target-context-tokens`（~256K 质量目标 vs 1M 硬上限）——allocator 打包目标收紧。
- **④** 真实 token 观测（含 `prompt_cache_hit_tokens`）——含 Reactor 跨线程 ContextPropagation + Spring AI Usage 映射缺口。
- **①** `EpisodeBudgetHook`（安全 vs 成本语义拆分，依赖 ④⑤ 的数据定阈值）。

## 个人 KB · 答案出处溯源（Top1）：答案附出处，按来源分组

> 个人 KB 改进路线 Top1。与上方"长上下文循环治理"是两条独立路线，同入 v6.4 滚动合集。

**Situation**：个人 KB 每条答案都"有主"（用户自己的笔记/卡片/对话记忆），可信 = 可溯源。但 RAG 召回的 `RecallHit`（带 docId/sourceLabel/createdAt/docName 等全套溯源字段）只被渲染成文本注入模型上下文、**hits 本身被丢弃**；前端 `done` 事件只发裸答案文本——用户无从知道"这段话来自我哪篇笔记/哪条记忆"。这是个人 KB 相对通用搜索最差异化的体验缺口。

**Task**：把召回命中的出处完整下发前端、**按来源分组**展示，且不喧宾夺主（答案才是主体）——同时不破坏模型注入上下文（sourceLabel 分类仍留给模型）。

**Action**（三轮迭代收敛）：
- **① 下发**：`Augmentation.buildAugmentationWithSources` 暴露 finalHits（新增 `AugmentationResult(block, hits)`，向后兼容）→ `BuildMessagesResult.sources` → `onComplete` 在 `done` 前发 SSE `sources` 事件；新增 `SourceRef` DTO + `from(RecallHit)`。
- **② 显示文档名而非分类**：`RecallHit` +`docName`、`UserMemoryDocument` +`doc_name` 字段（user-knowledge 检索原本映射时把这个字段丢了）、4 检索器 + ContextExpander 填充；`SourceRef.label` 优先文档名、文档去日期/记忆保留相对年龄、按名去重 + 封顶 5。
- **③ 分类分组**：`SourceRef` 加 `Kind`（MEMORY/DOC/CARD/PUBLIC），在 `from()` 里**从现有字段派生**（`sourceLabel="记忆"` + `id "card:"` 前缀 + 公开/官方）——**不动 RecallHit**（对抗验证：省去第 11 参 + 4 检索器 + withers 的改动面）；前端按 kind 分组（笔记/卡片/公开/记忆），每组 ≤2 + 溢出 `+N`，chip 只显示名称（snippet 进 hover tooltip），记忆组最弱化。

**Result**：
- 出处按分类分组、可溯源、安静地待在答案下方。后端 `SourceRefTest` 8 条 + 全量 **260/260 绿**，前端 vue-tsc 干净。
- 边界：CARD 判别靠 `id "card:"` 前缀（`cardId` 为 null 时回退 DOC，低概率）；snippet 用 `:title` tooltip（桌面 hover，移动端 click-toggle 待加）。

**代码**：`chat/dto/SourceRef.java`（+Kind 派生）、`rag/pipeline/recall/RagRecall.java`（AugmentationResult + buildAugmentationWithSources）、`chat/ChatService.java`（SSE sources）、4 检索器 + ContextExpander（docName）；前端 `types/chat.ts` / `api/chat.ts` / `store/chat.ts` / `components/MessageBubble.vue`。

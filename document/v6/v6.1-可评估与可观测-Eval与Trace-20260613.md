# Fish-Agent v6.1 可评估 + 可观测（Eval + Agent Trace）

> 日期：2026-06-13
> 主题：RAG/agent 自动化评测（golden set + LLM-judge）+ ReAct 执行 trace（TurnTrace）
> 状态：**已实施，经两轮审查通过**（mvn test 224 绿）
> 来源：虾皮「Agent 性能评估做过吗 / Agent Harness·Trace」、头条「怎么让智能体自己测东西」、Q3「召回效果怎么样」
> 关联：v6.0（booster/expander/contextualized 的收益本版量化）；面经驱动路线见 `temp/`

## 一、背景与动机

v5.5 只有**延迟**指标（`fish.rag.recall.duration`），`fish.rag.tracing` 是人工采样 review，209 测试测**代码正确性**不测**质量**，且无 agent 执行 trace——「召回效果怎么样」答不出数字、「Trace 是什么」答不上来。本版建**自动化质量评测 + ReAct 执行 trace**，并**量化 v6.0 的 B1/C2/D 收益**。

## 二、设计原则

1. **Eval + Trace 一对**：Trace 是 Eval 的数据地基（Eval 读 trace 的 ragInjected 算"注入对不对"）。
2. **ES-only 存储**：trace 不进 Redis、不要进程内 LRU，turn 结束 CAS 一次性 async 写 ES（避免撑爆 + 符 v5.6"不搞云原生"）。
3. **节点级颗粒度从已有 `Flux<NodeOutput>` tap 取**（不需 Observation 到节点级，框架天然给）。

## 三、方案与实施

### 3.1 Eval = A（召回 golden set）+ B（LLM-as-judge）

- **A 离线排序评测**：golden set（query + 带标签候选池）→ 跑 fusion+rerank+ProvenanceBooster → **precision@k / MRR / nDCG@k**（教科书级 graded nDCG）。**公平 A/B**（同候选池、等 base 分、单一 booster 公式）证明 v6.0 booster 把 nDCG 从 0.63 提到 1.0。
- **B LlmAnswerJudge**：接口 + score clamp（faithfulness / 答案相关性 / 上下文利用率），**不接真模型**（避免 CI 外部成本），留 live-eval 入口。
- **golden set**：20 条不重复真实 query（报销/休假/SLA/合同阈值…）+ `GoldenSetResourceTest` 回归测试防退化回 demo。

### 3.2 Trace = TurnTrace + NodeOutput tap + ObservationHandler（ES-only）

- **TurnTrace**：节点序列（`type=thought|action|observation|tool` + 逐节点耗时）+ `ragInjected` + `memoryInjected` 片段 + `tokenUsage`（预留）+ 终态。片段 ≤200 字，单条 1-3KB（全文不进 trace）。
- **埋点（三路解耦）**：① 节点级——`ChatAgent` 的 `Flux<NodeOutput>` `doOnNext` tap（显式 turnId，可靠，含 `classifyNodeType` 分类 + 相邻节点耗时）；② token——`TraceObservationHandler` 过滤 `gen_ai.*`；③ rag/memory——`ChatService` 组装消息时灌入。
- **存储**：turn 结束挂 `ChatTurnLifecycle` 的 CAS 一次性 `finishCallback` → `persistAsync` 写 ES（`fish-trace`），**异步不阻塞 SSE、失败仅日志**；`doc-max-chars` 封顶（超则丢尾节点 + 加 `trace-truncated` 标记）。`GET /admin/trace/{turnId}`（dev）。

### 两轮审查

首轮发现 7 项：① Observation handler 没注册（静默 no-op）；② nodes 非线程安全 `ArrayList`；③ `memoryInjected` 死代码；④ 节点全标 `node`/0ms；⑤ `doc-max-chars` 死配置；⑥ golden set 仅 1 对；⑦ 零参 `recordRagInjected` 并发不安全。

全部修复：handler 经 `ObservationRegistryCustomizer` 注册；nodes 改 `CopyOnWriteArrayList` + `AtomicInteger` order；`memoryInjected` 真接入（真实摘要/摘录/会话状态）；`classifyNodeType` 分 thought/action/observation/tool + `AtomicLong` 相邻耗时；`doc-max-chars` 读取 + 尾节点截断；golden set 扩 20 条 + 回归测试；删零参重载。**二轮 224 tests 绿，全 FIXED，无新 bug。**

## 六、面试 Trade-off

| 问题 | 回答要点 |
|---|---|
| 召回/记忆怎么测质量 | 离线 golden set + nDCG/MRR/precision@k + baseline vs booster 公平 A/B（证 v6.0 booster 提 nDCG 0.63→1.0） |
| Trace 是什么 / 怎么做 | ReAct 每步 thought/action/observation + 耗时；NodeOutput tap 捕获、CAS 一次落 ES、dev 端点可查 |
| 为什么 trace 不进 Redis | Redis 纯内存，全文 trace 会撑爆；ES 磁盘 + Kibana 白送 UI，turn 结束一次 async 写，符 v5.6 |
| token 怎么捕获 | Spring AI Observation handler 已注册，但跨线程 ThreadLocal 没传 → 运行时 token 待 ContextPropagation（诚实演进项） |

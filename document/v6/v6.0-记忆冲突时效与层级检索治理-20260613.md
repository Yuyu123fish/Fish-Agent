# Fish-Agent v6.0 记忆冲突、时效与层级检索治理

> 日期：2026-06-13
> 主题：长期记忆写入侧更新/失效（A2）、知识库检索冲突感知（B1）、邻片扩展（C2）、索引期上下文前缀（D）、记忆注入时间标签
> 状态：**已实施，经两轮审查通过**（mvn test 209 绿 + Python 校验）
> 来源：字节面试 Q6/Q7/Q8 暴露的 append-only 记忆与 flat chunk 短板

> 设计分阶段文档：`temp/v6.0-阶段{1,2,3}-记忆冲突与时效 / 知识库冲突感知 / 知识库检索准确度-20260613.md`

## 一、背景与动机

三道字节面试题同源——**信息会冲突、会过期，而 v5 的记忆/知识库只会 append，不会更新/失效/选优**：

- **Q6（抖音三面·挂点）**：30 天前"在北京上班"，现在"调到上海了"，旧事实该被取代。
- **Q8（头条一面）**：知识库两条资料冲突，AI 应按权威/新近选优并声明冲突，而非乱合并。
- **Q7（头条一面）**：大文档拆片后小块召回精度高但丢上下文。

代码核实（v5.6 现状）：

- 长期记忆抽取**已每轮异步触发**（`LongTermMemoryIngestionService.ingestFromUserInput`），不是短板。
- 短板在**写入处置**：`ElasticsearchLongTermMemoryStore.saveFacts` 每条新事实 cosine≥0.92 查重，命中即丢弃，**无 update / 无 supersede**——北京→上海死局（"调到上海了"与"在北京上班"语义过近，被当重复丢弃，旧"北京"永久留存）。
- KB 检索：`RagRecall` 四腿（BM25/kNN/RRF/qwen3-rerank）+ max-score 去重，**无权威/新近加权、无冲突检测**；chunk flat，`chunk_index` 未利用层级。

## 二、设计原则

1. **MVP 优先**：每条先给低风险、覆盖面试场景的版本，标出进化版与跳过项。
2. **复用优先**：复用已有调用/元数据，不增热路径 LLM 成本（写入 async，命中时才多一次判定）。
3. **共享脊梁 Provenance**：记忆事实与 KB chunk 共用溯源元数据，写侧（A2）与读侧（B1）共用。
4. **系统层 + 模型层双保险**：确定性 supersede/加权兜底 + 把写入时间交给模型推理。

## 三、方案与实施

### 3.1 共享 Provenance

```
Provenance { source; authority(0–1); createdAt; validFrom; superseded(仅记忆); validTo(仅记忆) }
```
记忆事实取全集（写侧 mutate），chunk 取 source/authority/createdAt（读侧加权）。

### 3.2 A2 写侧三选一（主攻 Q6）

`LongTermMemoryDeduplicator.isDuplicate` 升级为 `findSimilar`（返回 `SimilarFact{id,content,createdAt,score}`，top-K=5、score≥0.92；`isDuplicate` 保留兼容）。`saveFacts` 由"命中即丢弃"改为三态：

| findSimilar | judge 结果 | 处置 |
|---|---|---|
| 空 | — | WRITE |
| 命中 | SAME | DROP（真重复） |
| 命中 | CONFLICT | SUPERSEDE（旧 `superseded=true,validTo=now`，不删留审计）+ WRITE 新 |
| 命中 | NEITHER | WRITE |

- `MemoryConflictJudge` 复用 `@Qualifier("memoryChatModel")`（temp=0.1），prompt 判 SAME/CONFLICT/NEITHER；异常/未知降级 **NEITHER**（宁可都写也不误删新事实）。
- recall 双腿（BM25 + kNN）加 `must_not superseded=true`，**兼容旧数据无该字段**。
- 走查：北京→上海 → judge=CONFLICT → 旧失效 + 写新 → recall 只返"上海"。✅

### 3.3 B1 读侧加权 + 冲突感知 prompt（主攻 Q8）

- `ProvenanceBooster`（rerank 后、扩展/渲染前）：`boostedScore = rerankScore*(1+α·authority+β·recencyNorm)`，`recencyNorm=exp(-ageDays/halflife)`，α=0.15 / β=0.10 / halflife=180d，只在 tie 起作用，不压制相关性主信号。
- **`SourceAuthority`**（审查修复新增）：`PUBLIC`=组织/官方知识 authority=**1.0**，`PRIVATE`=用户知识 0.7，阈值 0.95→标签"官方"。Python `config.py` PUBLIC 默认 1.0 → 入库写入 → Java searcher 读 `doc.authority` → "官方"标签 + booster 真实可达（首轮审查发现此前无 1.0 来源、是死代码，本轮打通）。
- 渲染：每条 chunk 带 `[来源:官方/用户/公开·yyyy-MM]` 溯源标签 + 冲突处理指令（声明冲突 / 优先权威新近 / 引用双方 / 不确定则反问 / 不编造）。

### 3.4 createdAt 注入时间标签（Q2）

记忆事实注入带相对时间标签 `[记忆 · X前]`（`MemoryAgeLabel`，相对优先、必要时带绝对日期）。superseded 事实已被过滤，模型只见 active 事实 + 年龄，**自行推理渐进过期**——MVP 因此不做新近度衰减打分。

### 3.5 C2 邻片扩展（主攻 Q7）

`ContextExpander`：rerank topN 后，按 `doc_id + chunk_index ±N`（默认 1）取邻片、去重、按 chunk_index 拼接进命中块。**渲染预算保护首条中心命中**（审查修复）：超预算时首条命中**截断保留**而非整条 drop，后续命中超预算才 break。

### 3.6 D 索引期上下文前缀（主攻 Q7）

`contextual_indexing.py`：chunker 出片后、embed 前给每块前缀文档上下文，写 `content`（原文展示）/ `context_prefix` / `contextualized_content`（=前缀+content，BM25 + embedding 走它）。Java BM25 改 `contextualized_content + content` 双字段 should 查询，**兼容旧索引**。

- **诚实边界**：当前是**可插拔 generator + 确定性启发式前缀**（标题+页+序号），未接在线 LLM，避免摄取链路引入外部依赖。生产 generator = DeepSeek + prompt 缓存（文档作稳定前缀吃满自动 context caching，省 ~90%），接口已预留，后续同一函数注入即可。
- **重索引**：embedding 改用 contextualized 文本，旧文档需全量重索引才受益。

## 六、面试 Trade-off

| 问题 | 回答要点 |
|---|---|
| append-only 长期记忆的致命伤？ | 只会加不会废——矛盾事实共存、过期事实永留。北京→上海就是被 cosine 查重当重复丢弃。 |
| 怎么解决（Q6）？ | 写入侧三态（WRITE/DROP/SUPERSEDE）+ judge 判定；superseded 不删留审计；recall 双腿过滤失效。本质是 Graphiti 时序知识图谱 valid_to 关闭的轻量实现。 |
| judge 失败怎么办？ | 降级 NEITHER（都写）——宁可短暂双存也不误删新事实；superseded 可逆。 |
| KB 冲突怎么选（Q8）？ | 系统层：ProvenanceBooster 按权威(PUBLIC=官方=1.0)+新近加权；模型层：冲突感知 prompt 声明冲突、引用双方、不确定反问、不编造。双保险。 |
| contextual retrieval 是什么（Q7）？ | 索引期给 chunk 前缀文档上下文再 embedding/BM25，让孤立块可召回。搭了管线 + 可插拔 generator，当前启发式占位，生产 generator=DeepSeek+prompt 缓存（文档前缀吃满自动缓存省 ~90%）。 |
| 为什么不做新近度衰减打分？ | 把写入时间以相对标签注入，让模型自己推理渐进过期——比硬编码衰减更灵活、零打分复杂度。 |

## 七、后续实跑清单与进化版

**实跑**：
1. 启动核对记忆注入含 `[记忆 · X前]`、KB 注入含 `[来源:·]` + 冲突指令。
2. 接 DeepSeek generator 替换启发式前缀，跑一次真实文档索引核对 contextualized 收益 + 缓存命中成本。
3. 旧知识库全量重索引（embedding 改用 contextualized）。
4. 建 golden set（接 Q3）评测召回 recall/precision，调 α/β/authority 映射。

**进化版（v6.x）**：
- 记忆类型分桶（semantic/episodic/procedural，LangMem 式）——episodic 才需时效，时间标签只挂 episodic。
- importance 维度（Generative Agents 公式 recency+importance+relevance）。
- 时序知识图谱（Graphiti 风格 (s,p,o,valid_from,valid_to)）——Q6/Q8 根本解。
- C1 父文档检索（chunker 出 parent_id/section）。

## 改动概述

在 v4.1 知识卡片基础能力之上，完成三个递进阶段，实现从「卡片创建」到「卡片使用」到「知识溯源」的完整闭环：

1. **卡片分组层级化（Phase 3.2）** — `group_name` 扁平字符串升级为 `card_group` 实体表，支持无限层级树形分组 + 归一化去重 + AI 提取时感知分组树 + 前端树形 Tab + cascader 级联选择 + 面包屑路径
2. **RAG 召回闭环 + 复习模式（Phase 4）** — 新增 `UserKnowledgeCardSearcher`，confirmed 卡片参与四路 RAG 检索；前端新增翻转卡片复习模式；RAG 全链路 debug 日志增强
3. **切片可视化与双向桥接（Phase 5）** — 文档切片 K-Means 主题聚类 + 两级浏览 + 关键词搜索 + 切片↔卡片向量关联 + 卡片详情反向查源文档切片 + PDF CMap 乱码检测修复 + Worker 心跳线程连接关闭修复

## 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 分组存储 | 新建 `card_group` 实体表 | 支持树形层级 + 归一化去重，比 group_name 字符串灵活得多 |
| 归一化规则 | `trim().toLowerCase()` | 与 KeywordService 保持一致，避免"算法"和"算法基础"重复 |
| 卡片参与 RAG | 新建独立 Searcher | 与三路检索完全同构（text + vector 双路），自然参与 RRF 融合和 Rerank 精排 |
| K-Means 实现 | 手写纯函数 | 只有 K-Means 一个算法，不值得引入 Apache Commons Math |
| K-Means 初始化 | 确定性最远点优先 | 避免随机种子导致缓存失效，测试和重跑结果稳定 |
| 分组标题生成 | 一次性 LLM 调用 | 所有组的切片摘要拼成一个大 prompt，一次返回所有标题，避免 N 次 LLM |
| 切片↔卡片关联 | 向量余弦 > 0.70 动态计算 | 不落库，无需维护关联表；基于 embedding 语义相似度 |
| Redis 缓存 | 24h TTL | 聚类 + AI 摘要计算较重，缓存后体验流畅 |
| 分组过滤 | collectDescendantIds 递归收集 | 图谱/列表选父分组时，子分组的卡片也纳入 |

## RAG 四路召回架构

```
用户输入
  ↓
查询重写（可选）
  ↓
多子查询扩展
  ↓
四路并发检索（虚拟线程池 + UserContext 快照传播）
  ├─ 用户对话记忆 (fish-user-memory)
  ├─ 用户文档知识 (fish-user-knowledge)
  ├─ 用户知识卡片 (fish-knowledge-card)  ← Phase 4 新增
  └─ 公共知识库   (fish-public-knowledge)
  ↓
RRF 分数融合 / max-score 合并
  ↓
DashScope qwen3-rerank 精排（降级安全）
  ↓
Top-N 注入系统消息（带 id/score/source/preview 日志）
```

知识卡片 Searcher 特点：
- **三字段文本搜索**：title / content / keywords 任一命中即进入候选池（比其他 Searcher 只搜 content 更宽）
- **confirmed 状态过滤**：只检索已确认的卡片，pending/rejected 不参与
- **事实文本格式**：`知识卡片《标题》：正文 关键词：xxx` — 保留标题语义供模型识别

## 切片可视化流程

```
KnowledgeView → 点击「查看切片」
  ↓
ChunkDetailPanel 加载
  ↓
GET /chunks/groups → 缓存命中？→ 直接返回
                    ↓ 未命中
                    ES 查全部切片 → < 10 个？→ 单组"全部切片"
                                      ↓ ≥ 10 个
                                      K-Means 聚类 → LLM 批量生成标题+摘要 → Redis 缓存 24h
  ↓
概览视图：文档名 + 切片总数 + AI 摘要 + 主题分组卡片
  ↓ 点击分组
切片列表：分页 + 关键词搜索 + 关联卡片数
  ↓ 展开关联
向量检索：切片 embedding → fish-knowledge-card kNN → cosine > 0.70 → 关联卡片列表
  ↓ 点击卡片
跳转 /cards?openCard=ID → CardDetailPanel 打开
  ↓ 卡片详情"源文档切片"
反向向量检索：卡片 embedding → 知识库索引 kNN → cosine > 0.70 → 关联切片列表
  ↓ 点击切片
跳转 /knowledge?openChunks=taskId&chunkIndex=N → ChunkDetailPanel 打开
```

## Bug 修复记录

### 1. PDF CMap 乱码检测（Phase 5 期间发现并修复）

**问题**：PDF 字体 CMap 映射损坏时，PyMuPDF 提取的文本落入了泰文、缅甸文、阿拉伯文、埃塞俄比亚文等冷门 Unicode 区段。原有的 `should_use_ocr()` 三个检查全部未命中（无 `(cid:N)` 残留、无 U+FFFD/私用区、文本长度足够），导致乱码直接写入 ES。

**修复**：`python/fish_worker/parser/pdf.py` 新增 `has_noisy_scripts()` 第四个检查——统计"非常见文字区段"字符占比（>12% 阈值触发），有效覆盖 CMap 错误映射场景。实测乱码文本 95.1% 命中，正常中英文 0% 误触发。

### 2. Worker 心跳线程连接关闭异常（Phase 5 期间发现并修复）

**问题**：`mysql.py` 的 `close_current_thread_conn()` 未检查连接是否已关闭，PyMySQL 对已关闭连接调用 `close()` 抛出 `err.Error("Already closed")`。

**修复**：先清空引用再关闭、关闭前检查 `conn.open` 属性、外层 `except Exception: pass`。

## Debug 日志增强（Phase 4）

RAG 全链路 debug 日志从"只说精排命中"增强为完整诊断信息：

| 阶段 | 日志内容 |
|------|----------|
| 融合 | `[RagRecall] 融合 sid={}, strategy=RRF/maxScore, batchesIn={}, rawHits={}, dedupedCandidates={}` |
| 精排后无命中 | `[RagRecall] 精排后无命中 sid={}, rerankInput={}, rerankTopN={}` |
| 精排输入 | `[RagReranker] 开始精排 candidates={}, topN={}, model={}, query=[前60字]` |
| 精排输出 | `[RagReranker] 精排完成 input={}, output={}, topScore={}, lowestScore={}` + 前 5 条 id+score 明细 |
| 注入完成 | `[RagRecall] 注入完成 candidatePool={}, finalHits={}, blockLen={}, totalLatencyMs={}` |
| 每条命中 | `[RagRecall] #N id={}, score={}, source={}, preview=[前80字]` |

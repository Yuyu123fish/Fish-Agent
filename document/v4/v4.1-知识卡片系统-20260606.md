## 改动概述

在对话和知识库之上新增**知识卡片**子系统，将散落在对话中的知识沉淀为可复用的结构化卡片：

1. **卡片 CRUD + 统计** — 手动创建/编辑/删除 + 状态管理（pending/confirmed/rejected）+ 分组 Tab + 搜索筛选
2. **AI 自动提取** — 聊天页一键提取或被动提示（≥8 轮），LLM 分析对话生成卡片 + 关联关系，即时预览确认
3. **知识图谱** — vis-network 力导向图展示 confirmed 卡片和 4 种关系类型（related_to / contains / precedes / derived_from）
4. **关键词实体系统** — 自由文本关键词归一化为可查询实体，支持层次关系和同义词
5. **智能关联发现** — 多信号融合（关键词重叠 + 分组匹配 + 关键词层次 + embedding 相似度）自动发现缺失关系

## 新增 MySQL 表（3 张）

### knowledge_card（卡片主表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT AUTO_INCREMENT | 主键 |
| `user_id` | BIGINT NOT NULL | 所属用户 |
| `title` | VARCHAR(200) NOT NULL | 卡片标题 |
| `content` | TEXT NOT NULL | 卡片正文（Markdown） |
| `keywords` | JSON | 关键词数组，如 `["JVM","内存","GC"]` |
| `card_type` | VARCHAR(20) | concept / topic |
| `source_type` | VARCHAR(20) | chat / manual / knowledge |
| `source_id` | VARCHAR(100) | sessionId 或 documentId |
| `status` | VARCHAR(20) | pending / confirmed / rejected |
| `group_name` | VARCHAR(100) | 分组名称 |
| `created_at` / `updated_at` | DATETIME | 时间戳 |

索引：`idx_user_status` / `idx_source` / `idx_user_group`

### card_relation（关联表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT AUTO_INCREMENT | 主键 |
| `from_card_id` / `to_card_id` | BIGINT NOT NULL | 两端卡片 |
| `relation_type` | VARCHAR(30) | related_to / contains / precedes / derived_from |
| `confidence` | FLOAT | 置信度 0~1 |
| `created_at` | DATETIME | |

唯一索引：`uk_relation (from_card_id, to_card_id, relation_type)`

### keyword / card_keyword / keyword_relation（关键词实体系统，v4.1 阶段 3.1）

- **keyword**：归一化关键词实体，`normalized_name` 去重，`parent_id` 支持层次，`card_count` 冗余缓存
- **card_keyword**：卡片↔关键词多对多，`source` 标记来源（ai/manual）
- **keyword_relation**：关键词间语义关系（synonym/broader/narrower/related_to）

> 建表 SQL 见 `database/sql/fish_agent.sql`

## 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 卡片生成 | AI 提取 + 手动创建双通道 | 覆盖主动和被动两个场景 |
| 存储方案 | MySQL + ES 双写 | MySQL 事务保证一致性，ES 支持全文和向量检索 |
| 关联发现 | 多信号融合（关键词重叠 0.35 + 分组一致 0.20 + 层次匹配 0.20 + embedding 0.25） | 单一 embedding 阈值会遗漏"同领域但语义距离稍远"的卡片对 |
| 关键词存储 | 新建实体表 + 保留 JSON 字段 | 实体表用于查询发现，JSON 用于展示兼容 |
| 图谱库 | vis-network standalone | 力导向开箱即用，与暗色毛玻璃主题搭 |
| 提取触发 | 用户主动 + 被动提示（≥8 轮 + 知识性关键词） | 平衡控制感和可发现性 |
| 提取后流程 | 即时预览 → 勾选确认 | 趁热打铁，减少后续确认摩擦 |
| 分组方案 | group_name 字段（非新表） | 轻量 MVP，AI 提取时建议分组名 |
| 死锁防护 | 统一锁获取顺序（子表 → 关联表 → 主表）+ 拆分 OR DELETE | 避免 card_relation 和 keyword 表锁顺序不一致 |

## AI 提取管线

```
extractFromSession(sessionId, userId)
  ├─ 1. 加载对话（user + assistant，跳过 tool）
  ├─ 2. 对话加载策略
  │     ├─ ≤ 4000 tokens → 直接用原文
  │     └─ > 4000 tokens → 前半段 LLM 摘要 + 最近 20 条原文
  ├─ 3. Prompt 注入已有分组和关键词列表 → LLM 提取
  ├─ 4. JSON 解析 + 质量过滤（title 非空、content ≥ 30 字、最多 12 张）
  ├─ 5. 写入 knowledge_card（status=pending）+ 同步 keyword 实体
  ├─ 6. 建内部关联（同批 from_title/to_title → cardId）
  ├─ 7. 建外部关联（embedding → ES 向量检索 > 0.75 → related_to）
  └─ 8. 返回 ExtractResult（含完整卡片数据供即时预览）
```

## 智能关联发现算法

```
discoverRelations(userId)
  ├─ 1. 加载 confirmed 卡片 + card_keyword 关键词
  ├─ 2. 加载已有 card_relation（排除）
  ├─ 3. 剪枝：只对同组或共享关键词的卡片对计算
  ├─ 4. 综合评分：
  │     a. keywordJaccard × 0.35
  │     b. groupMatch × 0.20
  │     c. ancestorOverlap × 0.20
  │     d. embeddingSimilarity × 0.25（候选对 < 100 时启用）
  ├─ 5. score > 0.45 且无已有关联 → 建议为 related_to
  └─ 6. 按得分降序返回，最多 50 条
```
